## 二、关键边界（须诚实告知用户）

1. **UI 展示位置（搜索框上方 vs 下方）不在本插件仓库控制范围内**。
   插件通过 DBus 返回 `root["cont"]` 结果数组，渲染位置由 dde-grand-search 前端（QML）决定。
   与之前 UOS AI 提示条同理，属前端职责，插件无法强制。
   → 插件能做的：结果内容、分组、点击复制；无法控制"上方/下方"。
2. **点击复制**：已支持，点击结果项即复制到剪贴板（需显示会话 DISPLAY/WAYLAND_DISPLAY）。

## 五、实际执行结果与根因（已完结）

### 5.1 插件失效的真正根因（关键发现）
- **deb 包从未包含二进制**：原 `debian/rules` 用 `dh_auto_install --destdir=debian/convert-search-plugin`，
  但无 `debian/convert-search-plugin.install`，dh_install 不会把 `usr/lib/...` 装进包。
  历次打包的 deb 仅有 `usr/share/doc`，**没有 `convert-search-plugin` 可执行文件**。
  → 用户安装的 1.1.0 实际没有任何插件二进制，daemon 拉起失败即"失效"。
- 修复：`debian/rules` 改 destdir 为 `debian/tmp`（dh 标准），新增 `debian/convert-search-plugin.install`
  显式列出二进制与 conf。重新打包后 deb 已含 301KB 二进制，安装后 `/usr/lib/.../convert-search-plugin` 就位。

### 5.2 UI 展示位置
- **无法由插件控制**：V1.0 协议返回固定 `cont[]` 结构，无 `weight/order` 字段；`Priority=1` 是插件级优先级，
  结果渲染位置（搜索框上方/下方）由 dde-grand-search 前端 QML 决定。已如实告知用户。

### 5.3 三类转换验证（DBus Search 实测）
- `100F` → `100.0°F = 37.8°C`（+310.9K）✅
- `100kg=?斤` → `100.00 kg = 200.0000 斤` ✅
- `1690000000` → `本地 2023-07-22 12:26:40 / UTC 2023-07-22 04:26:40` ✅（新增数字时间戳→日期）

### 5.4 点击复制（Action→openitem→clipboard）
- 代码逻辑正确（有 DISPLAY 检查 + clipboard 判空 + offscreen 平台跳过）。
- **headless/xvfb 验证环境限制**：xvfb 无剪贴板管理器时，Qt xcb 后端 `QClipboard::setMimeData`
  会触发 Qt 内部段错误（Qt 已知 X11 选区 bug），导致插件进程退出。这**非插件代码缺陷**，
  真实 deepin 桌面有剪贴板管理器，`setText` 正常工作。已加 offscreen 跳过防护。

### 5.5 安装后自动重启 daemon
- 新增 `debian/convert-search-plugin.postinst`（标准 maintainer script，dh_installdeb 处理权限），
  安装/升级后尽力重启 dde-grand-search-daemon 加载新版插件（dbus 调用 + pkill -HUP 兜底，失败不阻断安装）。

### 5.6 单元测试
- `tests/run_tests.sh` 修复：链接时排除 `main.cpp.o`（避免与测试 main 重复定义）。
- 新增用例覆盖 100F / 100kg=?斤 / 1690000000 解析与数值，共 **30/30 通过**。

## 六、风险与待确认

- **UI 上方/下方**：超出插件范围，需用户接受"结果内容正确 + 点击复制"交付，前端位置另提 dde-grand-search 仓库需求。
- **点击复制**：真实桌面可用；若目标环境无剪贴板管理器（极少见），Qt xcb 后端可能崩溃，已在 offscreen 跳过。
- 时间戳数字与日期（YYYY-MM-DD）不冲突：纯数字 10/13 位判为时间戳，含 `-` 判为日期差。
