# 设计草案：其余五类转换的易用性优化

> 状态：**已实现**（2026-08-20，commit 1c74b1a / 2257aad / 82088e5 / 2022342 / 37cf506）。
> 日期：2026-08-20
> 关联：`docs/DESIGN-OMIT-TARGET.md`（单位/货币/热量"省略目标=全列"已实现）。
> 本期范围：时区时间 / 计算器 / 程序员工具 / 日期倒数 / 颜色 五类的易用性增强。

---

## 0. 统一基调（沿用已确认决策）

- **不舍上限，全列，UI 可展开**：同类可选结果一次性返回，长列表靠前端卡片展开/收起。
- **宽容解析**：无效/多余词不报错，回退到最合理的默认行为。
- **不引入新抽象、不新增文件**：在现有 provider 内调整结果生成逻辑；查询解析层尽量少动。

---

## 1. 时区时间（TimeProvider）

### 当前痛点
- 只返回**单个城市**的时间，无对照。用户常想"现在几点，和我家差多少" → 已有"本地时差"字段，但**没有同时列出本地时间**做并排对比。
- 输入必须含**已知城市关键词**；输入"现在几点""当前时间"等无城市词 → 无结果（被 Date/Program 分支抢或落空）。
- 没有"世界主要城市一览"式的快捷入口。

### 设计方案
1. **无城市词兜底**：输入 `时间` / `时区` / `现在几点` / `time` / `now` / `worldclock` 等（仅触发词、无具体城市）→
   返回**本地当前时间 + 一组常用参照城市**（北京/东京/纽约/伦敦/巴黎/悉尼，全列，可展开）。
2. **指定城市时并排显示本地**：结果卡除"目标城市时间 + 与本地时差"外，额外追加一行"本地此刻：HH:mm"。
3. **多城市一次查**：输入 `东京 纽约 伦敦`（空格分隔多城市）→ 逐城返回多条，每条标注与本地时差。

解析改动：`queryparser.cpp` 中 Time 分支需支持"无城市关键词但含 time 触发词"→ 标记为 `Time` 且 `city` 为空；
`TimeProvider::query` 对空 city 走"世界时钟"全列分支。

## 2. 计算器（CalcProvider）

### 当前痛点
- 整数结果已给 HEX/BIN/OCT，但**小数结果不给任何进制/格式变体**。
- 没有"表达式语法提示"：输错（如 `1/0`、`sqrt(-1)`、未知函数）→ 静默无结果。
- 进制转换只能"转一个目标"，不能"一个数同时看全部进制"。

### 设计方案
1. **小数结果增强**：浮点结果额外给"科学计数法"与"百分比"两种表述（如 `0.25 = 25% = 2.5e-1`）。
2. **求值失败给友好提示卡**（而非静默）：
   - 除零 / 域错误 → `无法计算：除数不能为 0` / `√负数无实数结果`；
   - 未知函数/符号 → `不支持的函数 xxx，可用：sqrt/sin/cos/...`，并附 help 提示。
   解析上 `CalcProvider::eval` 需区分"compute 失败原因"（目前 `compute` 只返回 bool）。
3. **进制一次全给**：`255 to hex` 仍单给；但新增"全进制"快捷——输入 `255 base` / `255 进制` → 同时返回 DEC/HEX/BIN/OCT 四条。

解析改动：基本无需动；`calcprovider.cpp` 内部扩展即可。失败提示需在 `compute` 返回错误码（最小改动：增一个 out 参数 `QString &err`）。

## 3. 程序员工具（ProgramProvider）

### 当前痛点
- 哈希只给**一种**算法结果（写 md5 给 md5）；但用户常想"同一串同时看 md5/sha1/sha256"做比对。
- ascii 只给单值；没给"一批字符"的逐字映射。
- 时间戳只有"当前"或"数字反查"，没有"指定日期→时间戳"（已在 DateTime 触发词 `转时间戳` 覆盖，但 Program 分支内未对齐说明）。

### 设计方案
1. **哈希一次全给**：输入 `hash hello` / `哈希 hello`（不指定算法）→ 同时返回 MD5 / SHA1 / SHA256 三条；
   指定算法（`md5 hello`）仍只给对应一条（保持精确）。
2. **ascii 多字符**：输入 `ascii hello` → 逐字符给出 `h=104 a=97 ...` 的紧凑多行（单字符/数字双向不变）。
3. **base64/url 双向同显（可选）**：输入 `base64 hello` → 除编码结果外，再附一行"解码验证：hello"（仅当内容可逆且无歧义时），方便核对。

解析改动：Program 分支基本不动；`programprovider.cpp` 内按"是否指定算法"决定单给/全给。

## 4. 日期 / 倒数日（DateTimeProvider）

### 当前痛点
- 仅支持"日期差""倒数""今天"三类；**没有"指定日期是星期几"**的纯查询（如 `2026-08-20 星期几`）。
- 倒数日只给"还有 N 天"，没有"距离目标还有几周几月"的多粒度。
- 没有"N 天后是几号"的反向查询（`2026-08-20 加 100 天`）。

### 设计方案
1. **星期几查询**：输入含日期 + `星期几`/`weekday` → 返回该日星期。
2. **倒数/日期差多粒度**：除"还有 N 天"外，附"约 X 周"或"约 Y 个月"（纯展示，不新增单位）。
3. **日期偏移**：输入 `2026-08-20 +100天` / `今天加30天` → 返回目标日期 + 星期。
   （解析上 `+N天` 需在 `queryparser.cpp` 日期分支识别，传给 `DateTimeProvider::run` 新子模式。）

实现：主要在 `datetimeprovider.cpp` 内扩展 `run()` 的子分支；`queryparser.cpp` 日期分支补充"星期几/加减天"关键词与 `+N天` 形态。

## 5. 颜色（ColorProvider）

### 当前痛点
- 输入 `#ff8800` → 给 RGB + HSL，但**没有反向"复制友好"的整行**（如 `rgb(255, 136, 0)` 可直接粘贴）。
- 不支持**中文/自然语言**描述色（如"红色""蓝色"），也不支持"随机色"。
- 没有"相近颜色/互补色"参考（设计师常需）。

### 设计方案
1. **双向互转全列**：任意输入（HEX/RGB/HSL）→ 同时给出**三种形态完整写法**（HEX/RGB/HSL 各一行，可直接复制）。
   当前已给，但需确认三种都输出（目前 RGB 输入给 HEX+HSL 两行，建议补齐第三行 RGB 自身回显）。
2. **常见色名快捷**：输入 `红色`/`蓝色`/`红色 #ff0000` 等 → 映射到预设色板（红/绿/蓝/黄/黑/白/灰 + 主题色），
   返回其 HEX/RGB/HSL；`颜色 随机` / `color random` → 生成随机 HEX。
3. **互补色/对比色参考**（可展开）：给输入色的互补色（色相 +180°）一行，辅助配色。

解析改动：`queryparser.cpp` 颜色分支需先排除"随机/色名"等非标准串（当前 `matchColor` 严格匹配 `#/rgb()/hsl()`）；
色名→HEX 映射在 `colorprovider.cpp` 内新增静态表。

## 6. 待确认问题（已拍板，2026-08-20）

1. **时区"无城市词"兜底** → **全列世界时钟**（常用城市：北京/东京/纽约/伦敦/巴黎/悉尼，可展开）。
2. **计算器失败提示** → **给友好提示卡**（除零/域错误/未知函数，简短说明 + help 提示）。
3. **哈希/进制"全给"默认行为** → **全给**（`hash xxx` 无算法时 MD5/SHA1/SHA256 三条；`xxx 进制` 一次给 DEC/HEX/BIN/OCT）。

> 用户原话决策：世界时钟全列 / 失败提示卡 / 哈希进制全给 / 互补色随机色纳入 / 日期加减星期纳入。

## 8. 结论

本期在"省略目标=全列/可展开/宽容"基调上，为其余五类补齐高频易用性缺口：
世界时钟兜底、计算器失败提示与小数增强、哈希/进制全给、日期星期与加减天、颜色三形态全列与色名映射。
均不引入新抽象，手术式修改现有 provider；解析层仅时区/日期/颜色三处需小补。
