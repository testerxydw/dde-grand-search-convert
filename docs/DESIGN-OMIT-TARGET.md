# 设计草案：省略目标单位时展示同类全部可转换单位

> 状态：**已实现**（2026-08-20，commit 4b2956b / 070ef9e）。
> 日期：2026-08-20

---

## 1. 问题来源

用户反馈：当前换算必须写 `=` 后的目标单位（如 `100kg=?斤` / `100kg=斤`）才能精确转换；
省略时（如 `100kg=`）只给一份写死的"常见单位"清单，且清单**不全、不随来源单位所属类别自适应**。

核心矛盾：

- 同类可转换单位**数量有限且固定**（线性单位约 8 个、温度 3 个、货币 6 个、热量 4 个）。
- 既然单位不多，省略目标单位时**应直接列出该类全部可转换单位**，而不是让用户猜、`=` 后该写什么。
- 这一原则对 单位 / 货币 / 热量 三类都成立（它们目标都是有限枚举）。
- 计算器、颜色、时间、日期、程序员工具 **本身不需要"目标单位"**，不在此设计范围。

当前行为（节选源码）：

- `unitprovider.cpp:173` 省略 `to` 时硬列 `"m"<<"cm"<<"km"<<"inch"<<"feet"<<"mile"`，与来源类别无关。
- `currencyprovider.cpp:67` 省略 `to` 时用 `kDefaultTargets`（固定 6 个）。
- `energyprovider.cpp:71` 省略 `to` 时硬列 `"kcal"<<"kj"<<"cal"<<"j"`。

---

## 2. 设计目标

1. 省略目标单位 → 输出**来源单位所属类别下的全部可转换单位**（同类穷举）。
2. 指定目标单位 → 行为不变（精确单条）。
3. 不引入新抽象、不新增文件；在现有 `convert()` 内调整 targets 生成逻辑。
4. 结果条数可控（同类枚举 ≤ 8 条），不爆炸。

---

## 3. 目标单位全集（按类别）

### 3.1 单位换算（线性 + 温度）

来源单位确定类别后，括号内的全部单位都作为候选目标（去掉来源自身）：

| 类别 | 候选目标单位（内部键） |
|------|------------------------|
| 长度 (length) | `m` `cm` `km` `inch` `feet` `yard` `mile` `li` `chi` `cun` |
| 重量 (mass) | `kg` `g` `mg` `lb` `oz` `斤` `两` `吨` `t` |
| 面积 (area) | `m2` `km2` `cm2` `公顷` `亩` `acre` |
| 体积 (volume) | `l` `ml` `gal` `m3` |
| 速度 (speed) | `kmh` `mph` `mps` `节` `mach` |
| 数据 (data) | `b` `kb` `mb` `gb` `tb` `bit` `kbit` `mbit` `gbit` |
| 温度 (temp) | `c` `f` `k`（三者互转，固定 3 个，已正确） |

注意：

- 每个类别候选键应**与 `unitprovider.cpp` 各 `*Factor()` 支持的键对齐**，新增键即同时扩充因子表与目标表，避免"能列不能算"。
- 中文单位（`斤`/`两`/`亩`/`码` 等）同样纳入，结果经 `I18n::unitName` 本地化展示。

### 3.2 货币

`kDefaultTargets` 改为**全部已支持币种**（与 `i18n.cpp` `currencyTable()` 对齐，非仅默认 6 个）：

```
CNY USD EUR JPY GBP HKD KRW RUB AUD CAD SGD THB INR TWD MOP
```

来源币种自身从结果中剔除。

### 3.3 热量

已为 `kcal kj cal j` 四类互转，与 `toKcalFactor()` 一致，**此类别现状已等于"全列"**，仅确认即可，无额外改动。

---

## 4. 交互语法（新）

| 输入 | 行为 |
|------|------|
| `100kg` / `100kg=` / `100kg=?` | 列重量类全部单位（kg→斤/两/g/lb/oz/吨…） |
| `100kg=斤` / `100kg 斤` / `100kg to 斤` | 精确：仅 `100kg = 200 斤` |
| `100F` / `100F=` | 列 `c` `k` 两个（源自身剔除） |
| `100usd` / `100usd=` | 列全部 15 个币种（除 USD） |
| `100kcal` / `100kcal=` | 列 kcal/kj/cal/j 互转 + 食物份数 |

等价触发词形式保持不变：`单位 100kg`、`convert 100kg` 等。

`=` 后为空或仅 `?` 一律视为"省略目标 → 全列"。

---

## 5. 实现要点（待确认后落地）

- 在 `UnitProvider` 内新增**每类别候选键表**（静态 `QHash<类别, QStringList>`），`convert()` 中 `to` 为空时取"来源类别对应的全表"而非写死的 6 个。
- 来源类别判定复用现有 `tryCategory` 的返回：`tryCategory` 已能识别类别，只需把"默认展示常见单位"替换为"该类别全表"。
- 货币：`kDefaultTargets` 扩充为全币种表（或改为引用 `currencyTable()` 的键集合）。
- 热量：现状即全列，无需改（确认即可）。
- 不参与：Calc / Color / Time / Date / Program 本就无"目标单位"概念。

---

## 6. 待确认问题（已拍板）

1. **全列条数上限**：~~是否全列还是设软上限~~ → **不舍上限，全列**。同类枚举即便 9~15 条也全部展示。
2. **UI 展示**：结果卡片**可展开**（前端收起/展开），避免长列表一次性占满搜索面板；插件侧只负责把全部候选结果返回，展开交互由 dde-grand-search 前端处理（插件不可控布局，仅保证数据完整）。
3. **`=` 严格化**：`100kg abc`（abc 非单位）→ **宽容回退为全列**并忽略无效词（`to` 视为空）。
4. 单位换算**不**额外加"常见参照"（如几袋大米），本期范围仅"省略目标=全列"。

> 决策日期：2026-08-20。用户原话："不舍上限，全列，可展开"。

---

## 7. 影响面与风险

- 仅改 3 个 provider 的 `convert()` 内 targets 生成；查询解析（`queryparser.cpp`）**无需改动**（`=` 后为空已能落入 `to.isEmpty()` 分支）。
- 触发词、help 卡片、README 需在落地后同步更新示例（如 `100kg=` 说明）。
- 测试：现有 `test_providers` 断言（如 `1kg≈2斤` 含 `2`）仍成立；需新增"省略目标→条数≥N"的断言。

---

## 8. 结论

设计核心一句话：**省略目标单位 = 展示来源类别下全部可转换单位（同类穷举），指定则精确单条。**
符合"单位不多、直接全列"的直觉，覆盖单位/货币/热量三类，不波及无目标单位的其他功能。
